Reboot or sign in. Your desktop arranges itself.

Every reboot, the same ritual: start the same applications, drag each window to the same display, maximise it, repeat. ScreenState does it for you. Capture your desktop once as a profile; from then on, signing in starts what was running and puts every window back on the display it belongs on.

How it works

Capture once. Restored after every reboot or sign-in.

  1. Capture. Arrange your desktop the way you like it and capture it. ScreenState lists every application it found and where each window sits; untick anything you want left out, name the profile and save. Applications waiting in the notification area are listed apart, unticked, for you to tick any the profile should keep running. Nothing is written until you confirm.
  2. Mark a default. The default profile is the one applied after you sign in. With only one profile, it is the default.
  3. Sign in. ScreenState waits in the notification area, starts whatever the profile says should be running and places each window the moment it appears, without waiting for the slowest application. A message on every display says the desktop is being prepared, then that it is ready.
  4. Read what happened. If anything could not be done, the splash says how many applications did not start and the report, in the tray menu, names each one with the reason.

The feature list

It puts the desktop back. Carefully.

What it does

  • Knows your displays apart, even two of the same model, by the identity Windows gives each screen rather than a number that changes.
  • Names applications by what survives their updates. A packaged application whose path moves with every update keeps its model id beside the path, so it is still started and its window still placed without capturing the profile again.
  • Leaves your keyboard alone. Nothing it places or starts takes the keyboard from the window you are typing in.
  • Leaves the taskbar clean. No button left lit, red or missing its icon once the restore is done.
  • Puts away what the profile does not name, by minimising it. At sign-in it can close those windows instead, if you turn that on.
  • Copes with change. A display that is gone sends its windows to the primary one; displays changing mid-restore do not stop it; a window that moves itself is put back once.
  • Applies any profile on demand from the tray or the manager, with a bar showing how far it has got. In the manager a button stops it, leaving what is already placed where it is.
  • Tells you when something is left over. While the last restore has an application it could not start or place, the tray icon carries a red badge and its tooltip says how many.

What it does not do

  • End another program. The only process it ever ends is its own agent, which setup stops before replacing it. It closes a window only where you have turned that on, only at sign-in and only for a window the profile being restored does not name.
  • Restore what is inside an application. Browser tabs, open documents and folders are the application's business.
  • Stacking order, Snap groups or virtual desktops. Where each window sits, yes; which is on top, no.
  • Encrypt your profiles. They are plain files in your own folder, holding application paths, window positions and display names.
  • Send your desktop anywhere. The one connection it makes asks whether a newer version exists, carries nothing about you and can be turned off.
  • Ask for administrator rights. Installed and run for your account alone.
  • Anything but Windows. Built and tested on Windows 11. Windows 10 will very likely work but is untested.

How it is built

Measured, not guessed.

Every behaviour above was measured on a real four-display desktop before it was written down; the specification records each measurement beside the requirement it settled. Nothing on this page is a number made up for it.

93

Requirements in the specification: 75 the product cannot do without and 18 more it carries.

100%

Of the functions that decide what a profile means and what a restore does are covered by tests. The build refuses to run below it.

19

Structural tests that fail the build if the architecture is broken or a rule is undone: nothing may end a program, nothing may start in front.

2

Timers a restore ever waits on: the ceiling that bounds a restore nobody touches and the wait for a taskbar button to stop flashing. Everything else is an event Windows reports.

Install

One file. No administrator rights.

  1. Download ScreenStateSetup.exe from the latest release.
  2. Run it and choose Install. It installs for your account only, so Windows never asks for administrator rights. The same program updates, repairs and uninstalls.
  3. Capture your desktop from the manager, save the profile and sign out and in again to watch it come back.

To remove it, uninstall from Settings > Apps. Your profiles live apart from the program, so they stay unless you tick the box that removes them too.
