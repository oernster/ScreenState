Changelog

What's new

Recent releases have focused on making ScreenState trustworthy on a real desktop: profiles that cannot quietly share a file or be applied without being listed, windows that come back in the order you left them, applications and displays named the way you know them. One release changed only the website, giving it a page for each job.

v1.4.0

Profiles that do what the list says

  • A profile file renamed or copied by hand in the profiles folder could be left out of the manager's list yet still be applied when you signed in. It is now named under the list with the reason; it is neither listed nor applied until it is put back under the file name the reason gives
  • Every change you make to a profile acts on the file it was read from. Two profile names can no longer end up sharing one file; saving a new profile never writes over another. Profiles saved by earlier versions keep working as they are
  • A profile edited by hand to drop its format is named as unreadable rather than guessed at; so is one that no longer says whether an application was running
  • When a profile held two programs from one packaged application, a restore could place one window for both. Each window now goes to one entry only, preferring the entry that names its program exactly; a program left without a window is reported as such
  • Setup recognises a running copy of ScreenState by its full path in the install folder before closing it, so a different program that shares the name is left alone
  • The update check opens only secure (https) links in your browser. A release pointing anywhere else is passed over and noted in the log
v1.3.0

A website with a page for each job

  • The program itself is unchanged in this release
  • The site is three pages instead of one long page: Home, Features and Install. Its address is now ernster.dev/ScreenState; the old address redirects there
  • The Install page carries a Windows card whose button fetches the setup program straight from the newest release, so the link cannot go stale. It shows the version, the file's size and why Windows may show a SmartScreen warning
  • Every section has its spacing back. Each page links its stylesheet by a fingerprint of its content, so a browser never pairs a new page with an old cached stylesheet
  • DECISIONS-TRADEOFFS.md sets out the deliberate choices ScreenState rests on: what was chosen, what was given up and what each one costs
v1.2.0

Applications and displays named the way you know them

  • The manager lists each application by its name, with what the profile does with it underneath in quieter text, instead of leading with its whole executable path. The name is worked out from what was recorded: Discord rather than Update, Claude rather than claude.exe
  • Nothing captured is hidden. Rest the pointer on an application for its whole path, how it is recognised and where each window was captured
  • Displays are named by where they sit among those connected (top, left, centre and right) instead of the long identity Windows gives them. A restore keeps the names it started with even if a display comes or goes; the identities are still listed when you rest the pointer on the report's summary
  • Pressing Apply no longer reshuffles which window is on top of which
  • A capture records which window is in front of which. A restore puts them back in that order before saying the desktop is ready, so a window you keep behind another stays there after every reboot. Nothing is activated to do it; profiles captured earlier hold no order until you capture again
  • With a dialog open in the manager, the title bar's cross, Alt+F4 and the taskbar button's Close do nothing until the dialog is closed. Quitting still quits
v1.1.0

A new layout for the manager; a restore you can stop

  • The main screen is three parts: the profiles down the left, what the selected profile arranges in the middle with every path shown whole, the buttons down the right. The settings moved to a dialog behind a new gear button
  • How long a restore waits for windows that have not appeared is yours to set, from 1 to 60 minutes. It stays at 15 until you change it
  • A restore applied from the manager can be stopped from the Applying panel; everything already placed stays where it is
  • The tray icon's tooltip is brought up to date after every restore. A red badge marks a restore that left an application it could not start or place, until a later restore completes
  • Starting ScreenState by hand opens the manager and moves nothing; only signing in arranges the desktop by itself
  • Opening the manager closes the message that says the desktop is being prepared. A click on that message closes it without ending the restore
  • A sign-in that closes windows now finishes on its own instead of waiting for your first key press, so taskbar buttons are no longer left red
  • Maximised windows are placed without taking the keyboard from the window you are typing in
  • A taskbar button that cannot be rebuilt is skipped on its own instead of stopping the rest
  • A packaged application such as Claude is matched by its model id after an update moves its path, so it is placed without recapturing the profile
  • A profile that cannot be read is named under the list with the reason instead of vanishing from it
  • The log no longer holds window titles, since a title can say what you were working on. It keeps the last ten restores instead of starting afresh past 1 MB
  • The donation button's tooltip now says first that ScreenState is free and stays free
v1.0.0

The first release: sign in and the desktop arranges itself

  • Capture the desktop as a profile: every application, where each window sits, which display it is on and whether it is maximised. Untick anything you want left out; nothing is written until you confirm
  • Profiles can be renamed, deleted after a confirmation naming the profile and marked as the default, which is the one applied after you sign in
  • At sign-in ScreenState starts every application the profile records as running and places each window the moment it appears. A message on every display says the desktop is being prepared, then that it is ready
  • Two monitors of the same model are never confused. A display that has gone sends its windows to the primary one
  • Nothing takes the keyboard and the taskbar comes back clean. Windows a profile does not name are minimised (or closed at sign-in, if you turn that on)
  • ScreenState never ends a program and never asks for administrator rights. A report of the last restore names each application it could not satisfy and why
  • One setup file installs, updates, goes back a version, repairs, reinstalls and uninstalls for your account alone. Uninstalling leaves your profiles unless you tick the box that removes them
  • An update check once per run carries nothing about you; turn it off and ScreenState makes no network connection at all
